# MyBrowser 1.1.5 Release Hardening Design

## Goal

Produce a reproducible `@alessai/mybrowser-mcp@1.1.5` release candidate from `MyBrowser/server` without relying on stale ignored `dist/` output. Publishing remains a separate, explicit user-approved action.

## Package contract

- Bump the server and extension package metadata, generated extension manifest source, CLI version, and MCP server identity from `1.1.4` to `1.1.5` so every first-party runtime version report agrees. Do not rewrite the existing README link to the already-published `1.1.4` extension archive before a new archive exists.
- Add a portable clean command that removes `dist/` through Node rather than shell-specific `rm`.
- Make the executable-bit step portable through Node rather than shell-specific `chmod`.
- Add `prepack` as the mandatory local gate. It runs clean, TypeScript checking, the complete server test suite, and a fresh production build.
- Keep the npm package allowlist restricted to `dist/`; source, tests, credentials, recordings, and development files must not enter the tarball.

## Verification

1. Run the full server and extension tests, checks, and production builds.
2. Run canonical npm audits. Server production and full audit must be clean; extension production audit must be clean. Existing WXT development-only findings are reported separately and are not bundled into the built extension.
3. Run `npm pack` from `MyBrowser/server`, which exercises `prepack` from a clean `dist/`.
4. Inspect the tarball file list and metadata for the expected package name, version, entrypoint, and minimal contents.
5. Install the tarball into an isolated SSD temporary project with the canonical npm registry.
6. Execute the installed `mybrowser-mcp --version` binary and require `1.1.5`.
7. Leave the repository clean except for intentional committed release changes.

## Failure behavior

- Any clean, check, test, build, pack, install, audit, or executable smoke failure blocks release.
- No hook is bypassed.
- No npm publish, GitHub release, tag, or push occurs without explicit user approval after verification.

## Scope exclusions

- WXT 0.20 migration and extension development-only audit cleanup.
- Navigation lifecycle, action-protocol, ARIA performance, and other existing P2 workstreams.
- Publishing, tagging, pushing, or changing credentials.
